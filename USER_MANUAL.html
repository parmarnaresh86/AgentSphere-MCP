2 System Requirements & Installation

Prerequisites

  • Windows server with Administrator rights for installation. The app runs as a Windows Service.
  • Node.js 20 LTS or newer (22 or 24 recommended). The bundled SQLite driver does not support Node 18.
  • Network access to your SAP B1 Service Layer, normally HTTPS on port 50000 (https://<server>:50000/b1s/v1).
  • Optional: direct access to the SAP HANA (port 30015) or MSSQL (port 1433) database, for DB SQL / Analytics V2 and batch/serial/bin picking.
  • A modern browser (Chrome, Edge or Firefox).
  • Optional AI provider: Anthropic Claude (direct), Azure OpenAI GPT-4o, or Claude on Azure AI Services. Without a key, the app runs in Standard (rule-based) mode.

Installation (recommended)

Right-click install.bat and choose Run as administrator. The one-touch installer then does the following:

  1. Checks the Node.js version, runs npm install, then runs npm run build.
  2. Asks for your SAP Service Layer URL, company DB, user and password and an AI provider, then writes the .env file. It generates a DB_ENCRYPT_KEY and can optionally test the SAP login.
  3. Registers the Windows Service "AgentSphere AI" (starts at boot) and adds a firewall rule "AgentSphere AI (port 3000)".
  4. Creates desktop shortcuts AgentSphere AI - Start / Stop / Status.
  5. Creates the local database (hanny.db) with the default login admin / admin123.
  6. Optionally installs the Claude Desktop MCP connector and the ChatGPT SQL Gateway connector.
  7. Opens http://localhost:3000 and prints the LAN URLs (http://<server-ip>:3000).
⚠️ Change the default passwords A new install creates the accounts admin and superadmin, both with password admin123. Change or replace them before going live. There is no in-app password change yet: create new accounts under User Management.

Manual alternative (developers): npm install → npm run build → create .env → npm run chat.

5.0 How the Copy-From Agents Work

All the document-conversion agents use the same four-step flow. On the P2P side these are PO → GRPO, GRPO → AP Inv and AP Inv → Credit; on the O2C side, Quot → Order, Order → Delivery, Delivery → AR Inv and AR Inv → Credit. Every agent screen has a white header with Back and a step badge, a step bar, and a welcome card that says "AI Guided Workflow".

  1. Pick the vendor / customer. Use the dropdown or filter and click Select →. Only parties with open source documents appear, each with an "(N open)" count.
  2. Pick one source document. The table shows Doc # / Date / Due / Reference / Total. Click Select →. Only open documents can be selected.
  3. Review the lines. Edit quantities and, where allowed, price, Disc%, tax code and warehouse. Then click ✅ Post <document>. Use ← Change <source> to go back.
  4. Done. A success card "✅ <document> Created Successfully" appears, with a 🖨️ Print link.
💡 Typing a document number You can type the source document number instead of clicking, for example 716, #716, SO 716 or GRPO 716. Hyphenated forms such as SO-716 are treated as a name search, so leave out the hyphen.

How to create a Purchase Request

  1. Choose Existing Item or New Item. A new item code is added to the Item Master automatically when the PR is posted.
  2. Pick the item from the list or search for it. The agent shows a 📦 Inventory Analysis (On Stock, Committed, On Order, Available, Reorder Level, Suggested Order Qty).
  3. Enter the quantity, or click the suggested-quantity chip. Then pick a warehouse, or Skip.
  4. Click Add Another Item to repeat, or Proceed to Header.
  5. Optionally pick a vendor ("Use <default vendor>" or Skip).
  6. Set the required date with the +7 days or +14 days chips, or type YYYY-MM-DD / DD-MM-YYYY. The date must be in the future; phrases like "next Friday" are not accepted.
  7. Add a comment or skip it, review the summary, then click ✅ Yes, Post to SAP.
  8. The result shows "✅ Purchase Request Created!" with the Document # and a 🖨️ Print Requisition link.

5.2 Purchase Order Agent

Purchase — P2P → AI Workflow → Purchase Order builds a new Purchase Order from scratch, without a PR. For a quick form instead of a guided agent, use Quick Create → Purchase Order. The flow is the same as the Sales Order Agent, with vendors in place of customers. The 📦 PO Builder panel on the right shows the vendor, each line with its total, and the Subtotal, Tax and Grand Total as you build the order.

  1. Vendor: choose from Select Vendor and click Select →, or type a vendor name or code in the chat to search SAP.
  2. Add Line Item: Item, Qty (default 1), Unit Price *, Disc%, Tax Code (filled from the item's purchase tax group, with the rate shown) and Warehouse. There is no automatic pricing, and every line needs a price greater than 0. A live preview shows Net / Tax / Line Total. Click + Add Line, then ✓ Done Adding Items. The running summary shows Subtotal, Tax and Grand Total.
  3. 📋 Purchase Order Ready to Post: set the Delivery Date (default: today + 7 days) and optional Comments, then click ✅ Post Purchase Order. The posting date is today; the delivery date is also used as the document date for tax.
  4. ✅ Purchase Order Created Successfully, with 🖨️ Print and Create New Purchase Order. If posting fails, correct the problem and click ✅ Post Purchase Order again.

5.3 PR → PO

Open Purchase — P2P → AI Workflow → PR → PO. The agent opens with a 📊 Pending PRs by Vendor table (Vendor, Code, PRs, Oldest, Overdue) and a checklist of open PRs.

  1. Tick one or more PRs. Use "Filter PRs by number or vendor…" to narrow the list, and 👁 View to open a PR's details.
  2. Click ✅ Proceed with N PR(s) →. All selected PRs are merged into one Purchase Order.
  3. Confirm the vendor. If the PRs have different vendors or none, the agent asks you to choose one, or you can pick Skip (Open Order). Then set the required date and comments.
  4. Fill in any missing Price or Whs in the PO Builder panel. Lines without a price are flagged.
  5. Click ✅ Yes, Post PO to SAP. The result "✅ Purchase Order Created!" lists the source PRs and has a 🖨️ Print PO link. The PO lines are linked to the PRs, so the PRs close.
ℹ️ Need separate POs?Run the agent once per vendor and select only that vendor's PRs. Reload PRs in the header refreshes the list.

5.4 PO → GRPO

Open Purchase — P2P → AI Workflow → PO → GRPO. It follows the copy-from flow in 5.0: Vendor › Purchase Order › Review Lines › Posted.

  • Header: Posting Date, Delivery Date, Vendor Ref / Delivery Note, Remarks.
  • Lines: Recv Qty, Unit Price, Disc%, Tax and Whse can all be edited.
  • 🏷️ Create Batches / 🔢 Create Serials appear for batch- or serial-managed items. 📍 Select Bins appears for bin-enabled warehouses.

8.0 Employee Expense Claims

Finance → Employee Expenses lets employees claim business expenses from their bills. Approved claims are posted to SAP as one Journal Entry: each bill is debited to its expense G/L, and the total is credited to the Employee Reimbursement Payable G/L, with the employee's name and SAP employee ID on the entry.

  1. My Expense Claims → ＋ New Expense Claim: give the claim a title, e.g. "Client visit — Chicago".
  2. Add bills: drop PDFs or phone photos (JPG, PNG) onto the claim. Each bill is read automatically: date, merchant, bill number, amount, tax and a suggested category. The bill is shown next to the lines so you can check it; ↻ Re-read reads a bill again. Correct anything that is wrong, choose a category for each line, then click Save.
  3. Submit for approval. Missing dates, amounts or categories are highlighted first. Bills older than the set limit, and bills that look the same as one on another of your claims, are flagged as warnings.
  4. Approval: approvers see the claim under Expense Approval and click Approve or Reject (a reason is required). A rejected claim goes back to the employee to correct and resubmit. Nobody can approve their own claim.
  5. Post: finance opens All Claims & Post JV → Ready to post, opens the claim, chooses the posting date and clicks Post Journal Entry to SAP. The journal entry number is shown on the claim. A claim can be posted only once.

Setting it up (finance / administrator)

  • Expense Settings: choose the Employee Reimbursement Payable G/L (credit), a default expense G/L, and a G/L for each expense category (Travel, Meals, Fuel…). Optionally post automatically when a claim is fully approved, or switch approval off.
  • Logins → SAP employees: link each AgentSphere login to its SAP employee (Employee master). Employees whose login is not linked cannot submit claims. The SAP reporting manager is shown next to each employee.
  • Expense Approval Master: create at least one approval template. Each stage has approvers: users, roles, or Employee's reporting manager (SAP). Stages can have rules, for example a director stage only when the claim total is more than 1,000. When several templates match, the one with the lowest priority number is used.
ℹ️ Who sees whatEmployees see only their own claims. Approvers see the claims they approve. Only users with All Expense Claims & Post JV see every claim and can post. These permissions are under Admin → Roles & Permissions → Finance → Employee Expenses.

Quotation Intelligence

Read-only, using the standard agent layout. Settings: Min. margin % (default 15) and Target margin % (default 25).

  • All open quotes (item code left blank): every open quotation line is checked against its cost, the customer's last price and the 12-month market price. Tools → Developer Tools → DB Connection opens DB Direct Connection. It is visible to users with the DB Connection permission. A direct connection powers DB SQL, Analytics V2, the DB Query Builder and batch/serial/bin picking.

  • Fields: Name, Type (SQL Server (MSSQL) or SAP HANA), Host / IP, Port (1433 or 30015), Database, Query Name (the HANA schema), User Name, Password, and Enable Password Encryption.
  • Click Test, then Save & Activate.
  • HANA details stored on an SAP connection (see 15.1) are connected automatically when you switch to that company.

Adding a connection

  1. In Add New Connection, under ⚡ Service Layer (OData API), enter the Connection Name and the Service Layer Base URL. It must include /b1s/v1 or /b1s/v2, e.g. https://server:50000/b1s/v2. Then enter the Company DB, Username and Password.

  3. Optional, 📋 Company-Specific Schema Hints: custom tables, UDF fields and views, and the labels for dimensions 1–5. These help the AI with company-specific data.
  4. Click Save Connection. To change a connection, click Edit, make your changes, and click Update Connection (or Cancel Edit). Leave the password blank to keep the existing one.
⚠ The default company is re-synced from .env at startupEach time the server starts, the connection for the company in SL_COMPANY is updated from SL_BASE_URL, SL_USER and SL_PASSWORD in .env and made active. If you move that company to a new Service Layer server, change the URL in both places, .env (SAP_B1_BASE_URL, SL_BASE_URL, COMPANY_1_URL) and the Connection Manager. Otherwise the old URL comes back after the next restart.

Switching companies

Click any company in the top-bar dropdown, or Switch in the Connection Manager. The switch applies to your session only, not to other users. The chat confirms "✅ Company Switched Successfully!". The top bar then shows the new Company DB, and all later queries and documents use that company. If the connection has no HANA details, any active DB Direct / Analytics V2 connection is disconnected.

16 Tips & Keyboard Shortcuts

Natural-language tips

  • Be specific about dates: "today", "this week", "last month", "January 2026", "last 30 days".
