AgentSphere AI for SAP Business One: System & Server Requirements

What the customer's IT team needs to prepare before installing AgentSphere AI on premise for 5–10 users: server sizing, software, SAP and HANA access, firewall ports, SSL, database choice and an optional Docker setup.

Version
2.0
Date
19 October 2026
Sizing basis
5–10 users, 1–3 SAP companies
Default deployment
Windows Server, Windows Service

1Architecture

AgentSphere runs as one Node.js application on a Windows server inside the customer network. Users open it in a browser. It reads and posts SAP documents through the SAP Business One Service Layer. It can also read the HANA database directly, read-only, for analytics. AI features call the chosen AI provider over the internet.

Solid line: required. Dashed line: optional (direct read-only HANA access).

  • The web UI, the APIs and the SAP tool server run in one Windows Service. The tool server is a child process over stdio and needs no extra port.
  • All SAP postings go through the Service Layer. Direct HANA access only runs SELECT statements.
  • The legacy Python FastAPI app in the project (port 8000) is not needed in production.

7SSL / HTTPS

7.1 Users → AgentSphere

The app always serves HTTP on port 3000. It also serves HTTPS on port 3443 automatically when these two files exist in the install folder:

certs\localhost-key.pem     private key (PEM, no password)
certs\localhost-cert.pem    certificate plus intermediate chain (PEM)

Keep these file names even when the certificate is issued for a real server name.

Certificate optionWhen to useNotes
Internal CA (Active Directory Certificate Services)Recommended for LAN useSubject / SAN must contain the name users type, for example agentsphere.company.local, and the IP if users use it. Domain PCs trust it automatically
Public certificate (DigiCert, Sectigo, Let's Encrypt)Access through a public DNS nameUsually installed on the reverse proxy on port 443
Self-signedTesting onlyBrowsers show a security warning

Converting a PFX file from IT:

openssl pkcs12 -in agentsphere.pfx -nocerts -nodes -out certs\localhost-key.pem
openssl pkcs12 -in agentsphere.pfx -clcerts -nokeys -out certs\localhost-cert.pem

Then add a firewall rule for TCP 3443, restart the AgentSphere AI service, and open https://<server-name>:3443. To force HTTPS, remove the port 3000 firewall rule once 3443 works. The app does not redirect HTTP to HTTPS by itself.

7.2 AgentSphere → SAP Service Layer

The Service Layer runs on HTTPS port 50000 and often uses a self-signed certificate. The installer sets NODE_TLS_REJECT_UNAUTHORIZED=0 so the connection works anyway.

Recommended for productionThat setting turns off certificate checks for all outbound HTTPS from the app, including the AI provider. Instead, install a CA-signed certificate on the Service Layer, or save the SAP certificate as certs\sap-ca.pem. Then set the system environment variable NODE_EXTRA_CA_CERTS to that file and set NODE_TLS_REJECT_UNAUTHORIZED=1.

8App database: SQLite or PostgreSQL

Use nowSQLite (hanny.db)

Built in. No database server, licence or port. Enough for 5–10 users.

Suggestion onlyPostgreSQL 16 / 17

Only for more than about 25–30 users, high availability, or a policy that requires a managed database server.

8.1 SQLite (current)

  • Created by the installer, runs in WAL mode, stored as hanny.db in the install folder.
  • Holds app users, sessions, SAP connection profiles, encrypted passwords, mail settings, prompt history, AI credit usage, the invoice OCR queue and local tables.
  • SAP business data is not stored here. SAP stays the system of record.

Backup (required): back up hanny.db and hanny.db-wal every day. Either stop the service for a moment, or take an online copy with sqlite3 hanny.db ".backup D:\Backup\hanny.db". Also back up .env, certs\ and data\. Keep 14–30 days. restore-db.bat restores the database from an earlier install folder.

8.2 PostgreSQL (if ever needed)

  • Development work: the app uses the synchronous SQLite API in about 316 places across 17 files. All of them must be rewritten for the PostgreSQL driver, and a data migration script written. It is not a setting that can be switched.
  • Infrastructure: PostgreSQL 16 or 17 (Windows or a Linux VM), 2 vCPU, 4–8 GB RAM, 50 GB SSD. Inbound TCP 5432 from the app server only, a dedicated agentsphere user, and scheduled backups with pg_dump or pgBackRest.
RecommendationKeep SQLite for this 5–10 user rollout. Review the choice if the user count or a high-availability requirement changes.

9.4 Changes needed in the project

The project has no Dockerfile today. Running it in Docker needs this development work, estimated at 2–3 days including testing:

  1. Database path setting. db.mjs always opens hanny.db in the app folder. Add a DB_PATH setting so the database lives on the /app/db volume. Mounting only the single file is not safe, because SQLite writes its -wal and -shm files next to it and they would be lost when the container is replaced.
  2. Add Dockerfile, .dockerignore and docker-compose.yml (drafts below).
  3. Leave out the Windows-only parts. node-windows, the .bat / .ps1 scripts and the Claude Desktop connector setup are not used in a container. Docker's restart policy replaces the Windows Service.
  4. Network folder for OCR intake. If invoices arrive in a Windows share, mount it on the Docker host (CIFS) and pass it into the container as a volume.
  5. Health check. Docker checks GET /login.html and restarts the container if it stops answering.

9.5 Draft Dockerfile

# ---- build stage ----
FROM node:22-bookworm-slim AS build
WORKDIR /app
RUN apt-get update && apt-get install -y --no-install-recommends \
      python3 make g++ libcairo2-dev libpango1.0-dev libjpeg-dev libgif-dev librsvg2-dev \
    && rm -rf /var/lib/apt/lists/*
COPY package*.json ./
RUN npm ci --omit=optional
COPY . .
RUN npm run build && npm prune --omit=dev

# ---- runtime stage ----
FROM node:22-bookworm-slim
WORKDIR /app
RUN apt-get update && apt-get install -y --no-install-recommends \
      libcairo2 libpango-1.0-0 libpangocairo-1.0-0 libjpeg62-turbo libgif7 librsvg2-2 tzdata curl \
    && rm -rf /var/lib/apt/lists/*
ENV NODE_ENV=production TZ=Asia/Kolkata CHAT_PORT=3000 CHAT_HTTPS_PORT=3443 DB_PATH=/app/db/hanny.db
COPY --from=build /app /app
RUN mkdir -p /app/db /app/data /app/logs && chown -R node:node /app
USER node
EXPOSE 3000 3443
HEALTHCHECK --interval=30s --timeout=10s --retries=3 CMD curl -fs http://localhost:3000/login.html || exit 1
CMD ["node", "chat-server.mjs"]

Optional: put a reverse proxy container (nginx, Caddy or Traefik) in front on port 443 to handle the SSL certificate. The app container then only needs port 3000 on the internal Docker network.

9.7 Docker operating rules

  • Run one container only. SQLite allows one writing server, so do not scale to several replicas. Several replicas would need PostgreSQL (section 8.2).
  • Update: docker compose pull then docker compose up -d. Data stays on the volumes.
  • Logs: docker compose logs -f agentsphere. Set Docker log rotation (max-size / max-file) so logs cannot fill the disk.
  • Backup: copy volumes/db (use the SQLite .backup command) and volumes/data every day.

11User PCs

  • Windows 10 / 11 or macOS with the latest Chrome or Edge (Firefox also works).
  • Screen resolution 1366 × 768 minimum, 1920 × 1080 recommended.
  • Network access to the server on port 3000 or 3443 (LAN or VPN). Nothing to install on user PCs.
  • Voice input needs HTTPS and microphone permission in the browser.

12Installation checklist

  1. 01Server ready per sections 2–3. Data drive created. Antivirus exclusions set.
  2. 02Node.js 22 LTS and the Visual C++ Redistributable installed. node -v shows v22.
  3. 03From the app server, https://<hana-server>:50000/b1s/v1/Login is reachable (port 50000 open).
  4. 04Optional: HANA SQL port reachable, tested with Test-NetConnection <hana-server> -Port 30041.
  5. 05Outbound port 443 to the AI provider tested.
  6. 06Release ZIP copied to D:\AgentSphere. Right-click install.bat and choose Run as administrator.
  7. 07SAP and AI details entered. The installer's SAP login test passes.
  8. 08Service "AgentSphere AI" is Running with startup type Automatic. http://<server>:3000 opens.
  9. 09Certificate files in certs\. Port 3443 opened. https://<server-name>:3443 works. Port 3000 closed if HTTPS is enforced.
  10. 10Default admin / superadmin logins replaced. User accounts created.
  11. 11Daily backup job set up for hanny.db, .env, certs\ and data\.
  12. 12diagnose.bat run. Its action plan shows no errors.
